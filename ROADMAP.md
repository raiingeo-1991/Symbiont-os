# SYMBIONT — ROADMAP

Roadmap описывает направление развития Symbiont.

Он отделяет уже реализованные и проверенные механизмы от текущей работы и будущих концепций.

Главный принцип развития:

> **Не заменять архитектуру без необходимости. Развивать существующие границы и укреплять уже работающие механизмы.**

Проект развивается сверху вниз:

**Философия → Архитектура → Компоненты → Интеграция → Проверка → Эволюция**

---

## 1. Реализовано

Следующие элементы уже существуют в canonical-линии проекта и были частью проведённых интеграционных работ:

- persistent Core state;
- persistent Identity;
- persistent Memory;
- EventJournal;
- Memory V2 components;
- Cognition / LLM integration;
- Quest system;
- P2P discovery and communication;
- Economy and Escrow;
- SecureSettlement;
- PermissionGate;
- SMSA security integration;
- SCP-1 cryptographic protocol;
- SCP-1 Zero-Trust verification;
- optional SCP-1 ↔ P2P integration;
- SCA-1 Continuity Shadow;
- Body / Bridge integration;
- integration and regression tests.

Эти пункты не означают, что каждый компонент завершён окончательно. Они означают, что соответствующая функциональность уже существует в проекте.

---

## 2. Проверенный фундамент

В ходе аудита были отдельно проверены важные интеграционные контуры.

### Continuity

SCA-1 работает как опциональный Shadow-контур:

`Core → EventJournal → SCA-1 Shadow`

Проверены self-test, handoff, rollback, replay и другие continuity-сценарии.

### Security

Проверены SCP-1 identity, подписи, replay protection, trusted nodes, Zero-Trust состояние и интеграция с P2P.

Проверена совместимость PermissionGate и SMSA.

### P2P

Проверены discovery, TCP/UDP взаимодействие, SCP-1 envelope и security boundaries.

### Economy

Проверены escrow-переходы и связка Quest → SecureSettlement → Economy.

### Memory

Проверены persistent memory, EventJournal и обработка больших объёмов записей.

Последний подтверждённый полный прогон тестов:

**92 tests passed.**

## 3. Текущий этап — Integration Hardening

На текущем этапе основная задача — не добавление новой архитектуры, а укрепление существующей системы.

Приоритеты:

- интеграционные тесты;
- регрессионные тесты;
- поиск скрытых связей между компонентами;
- проверка границ ответственности;
- исправление ошибок;
- проверка отказоустойчивости;
- проверка повторного запуска и восстановления состояния;
- проверка взаимодействия Core, EventJournal, Quest, P2P, Economy и Security;
- проверка связи Core и SCA-1;
- сохранение стабильности существующих API и интерфейсов.

Основной вопрос текущего этапа:

> **Действительно ли уже существующие части системы работают как единый Symbiont?**

---

## 4. Следующий этап — Quest Verification

Следующим крупным направлением является проверка того, как Quest превращается из действия в объективно проверяемую историю.

Планируется исследовать существующую цепочку:

`Quest → Execution → Proof → Verification → History → Reputation / Rank`

При этом новые механизмы не должны дублировать существующие Core-компоненты.

Перед реализацией необходимо сначала определить, какие части этой цепочки уже существуют в проекте.

---

## 5. Future Quest Development

Следующие направления являются будущей разработкой, а не заявленной готовой функциональностью:

### Objective Proof

Механизмы доказательства выполнения Quest без ручного утверждения со стороны человека.

### Verification

Машинная проверка того, соответствует ли результат условиям конкретного Quest.

### Reputation

Формирование репутации на основе истории проверенных действий, а не ручного назначения значения.

### Rank / Qualification

Связь истории Quest с уровнем квалификации и доступом к соответствующим действиям.

### Skills

Описание специализированных способностей, необходимых для определённых типов Quest.

### Machine-verifiable Quest Types

Типы Quest, для которых критерии выполнения могут быть формализованы и автоматически проверены.

### Witnesses

Распределённая система подтверждения результата, если одного локального источника доказательства недостаточно.

### Arbitration

Механизм разрешения споров вокруг результата или доказательства Quest.

### Quest History

Долгосрочная история выполненных и проверенных действий Symbiont.

### Distributed Verification

Возможность использовать несколько доверенных источников для проверки результата.

## 6. Continuity and Evolution

SCA-1 должен развиваться как отдельный continuity-контур, не превращаясь в замену Core.

Будущая работа может включать укрепление:

- identity continuity;
- state versioning;
- event history;
- rollback and recovery;
- integrity verification;
- handoff between execution environments.

Новые механизмы должны использовать существующие события и границы системы там, где это возможно.

---

## 7. Security Evolution

Дальнейшее развитие безопасности должно усиливать существующие границы:

- SCP-1;
- NodeIdentity;
- trusted nodes;
- replay protection;
- Zero-Trust verification;
- PermissionGate;
- SMSA;
- capability enforcement.

Не предполагается перенос всей security-логики внутрь Core только ради унификации.

---

## 8. Longer-Term Direction

После укрепления текущего фундамента проект может двигаться к более сложным сценариям:

- более глубокая распределённая работа Symbiont;
- перенос Core между средами выполнения;
- несколько Body вокруг одного Core;
- расширение P2P-взаимодействия;
- более развитая машинная верификация Quest;
- развитие Memory и associative retrieval;
- расширение локальных и внешних cognitive providers;
- контролируемое подключение дополнительных модулей.

Эти направления не являются обязательствами текущего этапа.

Они должны реализовываться только после проверки необходимости и совместимости с существующей архитектурой.

---

## 9. Что намеренно не является текущей задачей

На текущем этапе не планируется без необходимости:

- переносить всё в Core;
- создавать новые крупные архитектурные слои;
- заменять существующий P2P новым протоколом;
- превращать SCP-1 в сам P2P;
- заменять SCA-1 новым Core;
- добавлять функции только ради увеличения количества компонентов;
- выдавать концептуальные механизмы за реализованные.

Сначала проверяется существующая система.

Потом укрепляются реальные точки интеграции.

И только после этого добавляется следующий необходимый механизм.

---

## 10. Development Principle

Symbiont не должен постоянно начинать заново.

Каждый новый этап должен опираться на проверенный предыдущий этап.

```text
Philosophy
    ↓
Architecture
    ↓
Implementation
    ↓
Integration
    ↓
Testing
    ↓
Hardening
    ↓
Controlled Evolution
```

Главная цель roadmap — не сделать систему максимально большой.

Главная цель — сделать её максимально цельной относительно тех принципов, из которых она была построена.
