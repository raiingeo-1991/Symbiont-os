# Symbiont — русская документация

**Локально-ориентированная персональная AI-система, построенная вокруг идентичности, памяти, непрерывности и контролируемого развития.**

Symbiont создаётся не как очередной чат-бот.

Проект начался с другого вопроса:

> **Что останется от AI-системы, если изменятся устройство, модель, сеть или окружение?**

Ответ на этот вопрос постепенно становится архитектурой Symbiont.

Symbiont — экспериментальная система, в которой Core отделён от устройств, моделей и внешних сервисов, которыми он пользуется.

Философия идёт первой. Архитектура следует за ней. Код служит архитектуре.

---

## Что такое Symbiont

В основе Symbiont находятся несколько постоянных понятий:

- **Identity** — постоянная идентичность Symbiont.
- **Memory** — память, сохраняющая опыт за пределами одного процесса или диалога.
- **Cognition** — когнитивный слой, в котором языковые модели являются инструментами, а не самой идентичностью Symbiont.
- **Continuity** — сохранение идентичности и состояния при изменении окружения.
- **Core** — логический центр системы.
- **Bridge / Body** — интерфейсы, через которые Core получает доступ к устройствам и возможностям среды.

Телефон — не Symbiont.

Компьютер — не Symbiont.

Модель — не Symbiont.

Сеть — не Symbiont.

Это окружение и инструменты системы.

## Архитектура

Текущая система строится вокруг отдельных компонентов с чёткими границами ответственности.

```text
                    ┌─────────────────────┐
                    │       Symbiont      │
                    │        Core         │
                    └──────────┬──────────┘
                               │
              ┌────────────────┼────────────────┐
              │                │                │
              ▼                ▼                ▼
          Identity          Memory          Cognition
              │                │                │
              └────────────────┼────────────────┘
                               │
                         EventJournal
                               │
                               ▼
                         SCA-1 Shadow
                               │
        ┌──────────────────────┼──────────────────────┐
        │                      │                      │
        ▼                      ▼                      ▼
      Quest                  P2P                  Economy
        │                      │                      │
        └──────────────────────┼──────────────────────┘
                               │
                               ▼
                           Security
                               │
                     ┌─────────┴─────────┐
                     ▼                   ▼
                  Bridge                Body
```

Архитектура развивается эволюционно: новые возможности должны расширять существующие границы, а не постоянно заменять систему целиком.

## Память

Память — одна из исходных идей Symbiont.

Система должна сохранять опыт, а не начинать с нуля после каждого запуска.

Текущая реализация включает постоянное хранилище памяти, извлечение, журналирование и компоненты Memory V2.

Цель состоит не просто в сохранении текста. Память должна становиться частью истории системы.

---

## Непрерывность

Continuity — один из центральных архитектурных принципов Symbiont.

Текущая реализация содержит опциональный **SCA-1 Continuity Shadow**.

```text
Core → EventJournal → SCA-1 Shadow
```

SCA-1 наблюдает за событиями Core и поддерживает отдельный контур непрерывности со своими версиями состояния, хешами, историей событий и механизмами проверки.

SCA-1 не заменяет Core и не переносит систему непрерывности внутрь Core.

Включение:

```bash
export SYMBIONT_SCA1_SHADOW=1
```

Это позволяет сохранять принцип непрерывности как отдельный проверяемый механизм.

## Безопасность

В Symbiont несколько механизмов безопасности выполняют разные задачи.

### SCP-1

SCP-1 предоставляет аутентифицированные протокольные конверты, проверку свежести, структуры пакета и Zero-Trust состояния.

Опциональная интеграция с P2P:

```bash
export SYMBIONT_SCP1_P2P=1
```

Обнаружение узла и доверие к нему остаются разными понятиями.

### SMSA

SMSA предоставляет дополнительную границу безопасности и авторизации для поддерживаемых возможностей и settlement-операций.

Включение:

```bash
export SYMBIONT_SMSA=1
```

При этом Core PermissionGate остаётся прикладным интерфейсом явных разрешений.

## Quest и Economy

Quest в Symbiont — это не только работа.

Квест представляет действие или активность, которая может стать проверяемой частью истории системы.

Текущий реализованный путь связывает Quest, P2P, выполнение и экономический settlement:

```text
Quest
  ↓
P2P
  ↓
Execution
  ↓
SecureSettlement
  ↓
Economy / Escrow
  ↓
EventJournal
  ↓
SCA-1
```

В текущей реализации уже существуют жизненный цикл Quest, required-rank metadata, авторизация settlement и escrow-операции.

Объективное доказательство выполнения, полноценная Reputation, Qualification, Skills, машинно-проверяемые типы Quest, Witnesses, Disputes и Arbitration относятся к дальнейшему развитию, а не выдаются за уже завершённую функциональность.

Это принципиально: документация отделяет существующую реализацию от будущего.

## Текущее состояние

Symbiont остаётся экспериментальным проектом в активной разработке.

Текущий приоритет:

- интеграционные тесты;
- регрессионные тесты;
- исправление ошибок;
- проверка границ компонентов;
- проверка взаимодействия существующих механизмов;
- укрепление уже реализованной функциональности;
- сохранение стабильности Core.

Новые крупные архитектурные слои не должны добавляться без доказанной необходимости.

## Быстрый запуск

Canonical-директория проекта:

```bash
cd ~/Symbiont-os
python symbiont_core.py
```

Для полного порядка запуска и проверки интеграций используйте [`QUICKSTART.md`](../QUICKSTART.md).

Если используется локальная LLM, её можно запустить отдельно через llama.cpp и подключить через настроенный локальный endpoint.

## Принцип разработки

Symbiont строится сверху вниз.

**Философия определяет границы.**

**Архитектура реализует их.**

**Код выражает текущую реализацию.**

Реализация может меняться.

Принцип должен сохраняться.

> **The philosophy comes first.
> The architecture follows it.
> The code serves the architecture.**
