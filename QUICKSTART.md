# SYMBIONT — QUICKSTART

Этот документ описывает текущий способ запуска и базовой проверки canonical-линии Symbiont.

Canonical-директория:

```bash
cd ~/Symbiont-os
```

## 1. Проверка canonical-директории

```bash
cd ~/Symbiont-os
pwd
```

Ожидаемый путь в Termux:

`/data/data/com.termux/files/home/Symbiont-os`

Это текущая локальная source-of-truth линия проекта.

## 2. Запуск Symbiont

```bash
cd ~/Symbiont-os
python symbiont_core.py
```

После запуска Core показывает состояние Symbiont, включая identity, role, style, LLM, P2P и другие активные компоненты.

---

## 3. Локальный LLM

Если используется локальная модель через llama.cpp, сначала запусти LLM-сервер в отдельной сессии Termux.

Пример:

```bash
cd ~/llama.cpp
./build/bin/llama-server -m ~/models/<model>.gguf --port 11434
```

После этого в другой сессии Symbiont может подключиться к:

`http://localhost:11434`

Проверка LLM выполняется уже из самого Symbiont.

Если LLM не нужен для конкретного теста, Core может запускаться без него.

---

## 4. Проверка интеграций

### SCP-1 + P2P

Опциональная интеграция включается:

```bash
export SYMBIONT_SCP1_P2P=1
```

Для SCP-1 должны быть настроены trusted nodes. Discovery и trust остаются разными понятиями.

### SCA-1 Continuity Shadow

```bash
export SYMBIONT_SCA1_SHADOW=1
```

SCA-1 работает как дополнительный continuity-контур вокруг существующего Core.

Основной поток:

`Core → EventJournal → SCA-1 Shadow`

SCA-1 не заменяет Core и не должен изменять его состояние.

### SMSA

```bash
export SYMBIONT_SMSA=1
```

SMSA добавляет security/authorization boundary для поддерживаемых возможностей и settlement-операций.

---

## 5. Полный набор тестов

Из canonical-директории:

```bash
cd ~/Symbiont-os
python -m pytest -q tests
```

Это основной регрессионный набор проекта.

Перед публикацией изменений следует убедиться, что полный набор тестов проходит.

---

## 6. Диагностика

Если что-то не работает, сначала определить границу отказа, а не менять архитектуру.

Рекомендуемый порядок:

`Core`

↓

`EventJournal`

↓

`Quest / P2P / Economy`

↓

`Security`

↓

`SCA-1`

↓

`Body / Bridge`

Проверять следует существующие соединения и взаимодействия компонентов.

Новые архитектурные слои не добавляются только для устранения локальной ошибки.

---

## 7. Текущий принцип разработки

Symbiont остаётся экспериментальным проектом, находящимся в активной разработке.

Текущий приоритет:

- интеграционные тесты;
- регрессионные тесты;
- исправление ошибок;
- проверка границ компонентов;
- проверка взаимодействия существующих механизмов;
- сохранение стабильности Core.

Новые крупные архитектурные слои не должны добавляться без необходимости.

Для архитектуры используйте `MANIFEST.md`.

Для направления развития используйте `ROADMAP.md`.

Для концепции проекта используйте `PHILOSOPHY.md`.

---

## 8. Важно

Не используйте старые пути вроде `~/symbiont` для работы с canonical-линей.

Текущая canonical-линия:

`~/Symbiont-os`

Не публикуйте секреты, приватные ключи, recovery-фразы или другие чувствительные данные.

---
